# 毕业设计项目概念介绍

## 一、项目简介

**课题名称**：数组类型变量状态引导的模糊测试工具的设计与实现

**一句话概括**：在 AFLGO 定向模糊测试框架的基础上，增加对数组变量运行时状态的感知和引导能力，使模糊测试工具能够更高效地发现数组越界类漏洞。

---

## 二、核心概念解释

### 2.1 模糊测试（Fuzzing）

**类比理解**：假设你有一个函数 `process(int x)`，你怀疑当 `x` 取某些特殊值时会崩溃。你可以手动尝试 0、-1、100、999999 等值，但手工尝试永远无法覆盖所有可能。模糊测试就是**自动化地、大规模地生成随机或半随机的输入**，喂给目标程序，观察它是否会崩溃。

**技术定义**：模糊测试是一种通过向目标程序输入大量畸形或半畸形数据，监测程序是否出现崩溃、内存泄漏等异常行为，从而发现安全漏洞的自动化测试技术。

**和传统测试的区别**：
| 传统测试 | 模糊测试 |
|---------|---------|
| 人工设计测试用例 | 自动生成测试用例 |
| 验证功能是否正确 | 发现程序何时崩溃 |
| 用例数量有限 | 每秒可执行数千次测试 |
| 关注"程序做了该做的事吗" | 关注"程序会做什么不该做的事吗" |

### 2.2 覆盖率引导的灰盒模糊测试（Coverage-Guided Greybox Fuzzing）

**灰盒测试**：介于黑盒（完全不看代码）和白盒（完全分析代码）之间——知道代码的基本结构，但不做深度分析。就像你看得到程序的骨架，但不知道每一块骨头的精确作用。

**覆盖率引导**：模糊测试工具会在目标程序中"插桩"（插入监控代码），追踪哪些代码行被执行了。如果某个输入触发了之前从未执行过的代码，就把这个输入保存下来作为"优质种子"，基于它继续变异。这就像探索迷宫——每发现一条新路，就标记下来，以后从这条路继续探索。

**边覆盖率**：不只记录"哪些行跑了"，更精确地记录"哪些分支跳转被触发了"。例如 `if (x > 10)` 这个分支，记录的是 `x > 10` 为真和为假两种路径各自是否被覆盖。

### 2.3 AFL / AFLGO

**AFL（American Fuzzy Lop）**：由 Google 安全研究员 Michal Zalewski 在 2014 年发布的经典模糊测试工具，以其简单高效的设计在安全社区引起广泛关注。

**AFLGO**：在 AFL 基础上发展的**定向模糊测试**工具。它不仅追求覆盖率最大化，还能根据用户指定的目标代码位置（如补丁修改处），通过控制流图距离计算引导测试资源向目标区域集中。AFLGO 是本项目的基础框架。

**与 AFL++ 的关系**：AFL++ 是 AFL 的社区增强版，功能更丰富。AFLGO 专注于"定向"场景，本项目的数组状态引导机制正是在 AFLGO 的定向能力之上构建的。

### 2.4 数组越界漏洞（Array Out-of-Bounds）

这是本项目专注的漏洞类型。

**什么是数组越界**：
```c
int arr[10];    // 定义一个长度为 10 的数组
arr[40] = 1;    // 越界！索引 40 超出了有效范围 [0, 9]
arr[-1] = 1;    // 越界！索引不能为负数
```

**为什么危险**：
- **越界写入**（CWE-787）：可能覆盖相邻内存区域的敏感数据、函数返回地址等，甚至可能被利用来执行任意代码
- **越界读取**（CWE-125）：可能读取到密码、密钥等相邻内存中的敏感信息

在 C/C++ 中，数组没有 Java 那样的自动边界检查（`ArrayIndexOutOfBoundsException`），所以越界访问不会立即报错，而是表现为难以排查的内存损坏问题。

### 2.5 LLVM / LLVM Pass / GEP 指令

**LLVM**：一套模块化的编译器基础设施。Clang 就是用 LLVM 构建的 C/C++ 编译器。

**LLVM IR（中间表示）**：编译器在将源代码翻译成机器码的过程中，会先将其转换成一个中间形式，这就是 LLVM IR。它比源代码更"底层"（更接近汇编），但比汇编更"可读"。

**LLVM Pass**：相当于 LLVM 的"插件"。本项目实现了两个自定义 Pass：
- `ArrayAnalysisPass` — 静态分析 Pass，扫描 IR 中的 GEP 指令，识别数组变量并计算影响力分数
- `ArrayInstrumentPass` — 插桩 Pass，在 GEP 指令后插入运行时监控代码

**GEP（GetElementPtr）指令**：LLVM IR 中用来计算数组/结构体元素地址的指令。例如 C 代码 `arr[5]` 在 IR 中对应一条 GEP 指令。GEP 的结构直接暴露了数组的类型、长度和访问索引，使其成为检测数组访问的最佳切入点。

### 2.6 状态多样性得分（SDS）与信息熵

**SDS（State Diversity Score）**：衡量"我们测试了数组索引空间的多少比例"。SDS = 0 表示所有数组的索引都只访问了第一个位置，SDS 接近 1 表示每个数组的索引空间都被充分探索过了。

**信息熵（Entropy）**：衡量"索引访问的分布够不够均匀"。热力学中的"熵"度量系统的混乱程度，在信息论中，熵度量概率分布的不确定性。对数组访问而言，熵高表示访问均匀分散在各个索引位置（好），熵低表示访问集中在少数几个位置（差）。

**两者区别**：SDS 看"覆盖了多大的面"，熵看"分布得均不均匀"。两者的互补使用可以区分"表面覆盖广但实际深度不足"的情况。

### 2.7 双重引导体系

本项目的核心创新在于将**路径距离引导**与**数组状态多样性引导**相结合：

- **距离引导**：继承 AFLGO 的控制流图距离计算，让测试资源向目标代码区域集中
- **状态引导**：通过数组状态多样性得分（SDS + 香农熵），引导测试探索数组边界的未覆盖区域
- **融合评分**：$Q = \alpha \cdot D' + \beta \cdot S + \gamma \cdot E$，其中 $D'$ 为距离评分，$S$ 为 SDS，$E$ 为归一化熵

## 三、项目架构概览

```
源代码（C 程序）
    ↓  编译时
[ArrayAnalysisPass] — LLVM Pass 插件（静态分析）
    |  扫描 GEP 指令，识别数组变量
    |  计算数组影响力分数
    ↓
[ArrayInstrumentPass] — LLVM Pass 插件（插桩）
    |  在 GEP 后插入 __afl_report_array_state() 调用
    |  传递：array_id, index, access_type, line_number
    ↓
插桩后的可执行程序（AFLGO 定向插桩 + 数组状态插桩）
    ↓  运行时（每次执行）
[array_state_runtime] — 运行时状态库
    |  __afl_report_array_state() 被调用
    |  记录 (数组ID, 索引值, 读/写, 行号)
    |  更新 SDS、熵等指标
    |  写入反馈文件 /tmp/array_feedback.txt
    ↓
[AFLGO 调度器 + 测试用例选择模块]
    |  读取 SDS 反馈 + AFLGO 距离评分
    |  计算综合得分 Q = α·D' + β·S + γ·E
    |  根据综合得分分配变异能量
    ↓
AFLGO 引擎
    |  管理种子队列
    |  调度测试执行
    |  收集路径、覆盖率和崩溃数据
```
