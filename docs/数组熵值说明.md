# 答辩备答：数组访问熵与全局归一化熵得分

## 问题

你的论文中为什么要引入信息熵？SDS 和熵有什么区别？

## 一句话回答

SDS 衡量的是数组状态空间的**覆盖广度**（踩到了多少不同槽位），但无法区分"覆盖充分但分布集中"和"覆盖充分且分布均匀"两种情况；信息熵衡量访问分布的**均匀程度**，弥补了 SDS 的盲区。

---

## 详细解释

### 1. 动机：SDS 的盲区

两个数组 SDS 均为 0.5，但访问模式完全不同：

| 场景 | unique_slots | 访问分布 | SDS | 实际探索质量 |
|------|-------------|---------|-----|-------------|
| 均匀分布 | 128 | 128 个槽位各访问 1 次 | 0.5 | 覆盖充分，探索深入 |
| 集中分布 | 128 | 2 个槽位各访问 64 次，其余 126 个各 1 次 | 0.5 | 集中在少数区域，探索不充分 |

SDS 只看"覆盖了多少个槽位"（通过 `visited_slots` 位图），看不出访问是均匀散布还是扎堆。信息熵通过 `slot_access_count` 的频次分布，能区分这两种情况。

### 2. 数组访问熵 $H_i$

#### 公式

$$H_i = -\sum_{j=1}^{N_i} p_{ij} \log_2 p_{ij}$$

其中 $p_{ij} = c_{ij} / n_i$：
- $c_{ij}$ = 槽位 $j$ 的访问次数（`slot_access_count[j]`）
- $n_i$ = 该数组总访问次数（`access_count`）
- $N_i$ = 256（总槽位数）

#### 公式原理拆解

这个公式看起来抽象，但背后的直觉很简单——**你平均每次"猜"对一次访问落在哪个槽位，需要问多少个"是否"问题？**

##### 第一步：$\log_2 p_j$ 衡量"这个结果有多让人意外"

- 如果某个槽位 j 总是被访问（$p_j = 1$），那 $\log_2 1 = 0$——一点都不意外，不需要问问题
- 如果某个槽位很少被访问（$p_j$ 很小），那 $\log_2 p_j$ 是个很大的负数——很意外，需要很多问题才能猜中

举个例子，4 个槽位时：

| $p_j$ | $\log_2 p_j$ | 含义 |
|-------|-------------|------|
| 1 | 0 | 100% 会发生，毫无意外 |
| 1/2 | -1 | 有点不确定，需要 1 个问题 |
| 1/4 | -2 | 更不确定，需要 2 个问题 |
| 1/256 | -8 | 非常不确定，需要 8 个问题 |

##### 第二步：$-p_j \log_2 p_j$ 加权平均

加负号把 $\log_2 p_j$ 变成正数，再乘以 $p_j$ 做加权平均：$-p_j \log_2 p_j$。

得到的就是"平均需要问多少个问题"——即**不确定性的大小**。

##### 第三步：三个具体数值例子（4 个槽位，方便手算）

为了让数字直观，先假设 $N_i = 4$（最大熵为 $\log_2 4 = 2$）：

**例 A：完全集中** — 永远只访问槽位 0

| 槽位 | 访问次数 | $p_j$ | $-p_j \log_2 p_j$ |
|------|---------|-------|-------------------|
| 0 | 100 | 1.0 | $-1.0 \cdot \log_2(1.0) = 0$ |
| 1 | 0 | 0 | $0$（约定 0 log 0 = 0） |
| 2 | 0 | 0 | $0$ |
| 3 | 0 | 0 | $0$ |

$H = 0 + 0 + 0 + 0 = \textbf{0}$ → 完全没有不确定性，因为每次猜"槽位 0"就一定对。

**例 B：完全均匀** — 4 个槽位各访问 25 次

| 槽位 | 访问次数 | $p_j$ | $-p_j \log_2 p_j$ |
|------|---------|-------|-------------------|
| 0 | 25 | 0.25 | $-0.25 \cdot \log_2(0.25) = -0.25 \cdot (-2) = 0.5$ |
| 1 | 25 | 0.25 | $0.5$ |
| 2 | 25 | 0.25 | $0.5$ |
| 3 | 25 | 0.25 | $0.5$ |

$H = 0.5 + 0.5 + 0.5 + 0.5 = \textbf{2.0}$ → 达到最大值，因为你平均需要问 2 个"是否"问题才能猜对。

**例 C：分布不均** — 一个槽位访问 70 次，一个 20 次，两个各 5 次

| 槽位 | 访问次数 | $p_j$ | $-p_j \log_2 p_j$ |
|------|---------|-------|-------------------|
| 0 | 70 | 0.7 | $-0.7 \cdot \log_2(0.7) = -0.7 \cdot (-0.514) \approx 0.36$ |
| 1 | 20 | 0.2 | $-0.2 \cdot \log_2(0.2) = -0.2 \cdot (-2.322) \approx 0.46$ |
| 2 | 5 | 0.05 | $-0.05 \cdot \log_2(0.05) = -0.05 \cdot (-4.322) \approx 0.22$ |
| 3 | 5 | 0.05 | $0.22$ |

$H = 0.36 + 0.46 + 0.22 + 0.22 = \textbf{1.26}$ → 介于 0 和 2 之间，因为集中在槽位 0 和 1，但也不是完全确定。

对应到真实代码（$N_i = 256$），最大熵为 $\log_2 256 = 8$，$H_i$ 取值在 $[0, 8]$ 之间。**$H_i$ 越大，说明数组访问散布得越均匀、越充分。**

#### 为什么能用"不确定性"衡量"探索均匀程度"？

这里的转化逻辑是：

```
访问越均匀 → 越难预测下一次落在哪个槽位 → 不确定性越高 → 熵越大
访问越集中 → 越容易预测（猜最常访问的就行） → 不确定性越低 → 熵越小
```

所以 $H_i$ 大 = 探索均匀，$H_i$ 小 = 探索集中——这个性质正是 SDS 不具备的。

#### 代码实现（array_state_runtime.c）

```c
float __afl_get_entropy(uint32_t array_id) {
    array_state_t *arr = find_or_create_array(array_id, NULL);
    if (!arr || arr->access_count == 0) return 0.0f;

    float entropy = 0.0f;
    for (int i = 0; i < MAX_INDEX_SLOTS; i++) {
        if (arr->slot_access_count[i] > 0) {
            float p = (float)arr->slot_access_count[i]
                     / (float)arr->access_count;
            entropy -= p * log2f(p);          // -p * log2(p) 累加
        }
    }
    return entropy;
}
```

关键点：数据来源于 `slot_access_count[256]`（频次统计），而非 `visited_slots[256]`（位图）。前者保留了"每个槽位被访问了多少次"的分布信息，后者只记录了"是否被访问过"。

### 3. 全局归一化熵得分 $E$

#### 公式

$$E = \frac{1}{m} \sum_{i=1}^{m} \frac{H_i}{\log_2 N_i}$$

#### 为什么需要归一化？

$H_i$ 的值取决于槽位数 $N_i$。假设现在程序中有两个数组：

| 数组 | 槽位数 $N_i$ | 最大可能 $H_i$ |
|------|-------------|---------------|
| buffer_A | 256 | $\log_2 256 = 8.0$ |
| buffer_B | 64 | $\log_2 64 = 6.0$ |

如果 buffer_A 算出来 $H_A = 4.0$，buffer_B 算出来 $H_B = 4.0$，它们的绝对熵一样，但含义不同：

- **buffer_A** (256 槽位)：$4.0 / 8.0 = 0.5$，只达到最大不确定性的 50%
- **buffer_B** (64 槽位)：$4.0 / 6.0 \approx 0.67$，达到了最大不确定性的 67%

显然 buffer_B 探索得更充分。所以**必须除以各自的 $\log_2 N_i$ 消除规模差异**，才能跨数组比较。

#### 两步操作拆解

**第一步——归一化：** $\frac{H_i}{\log_2 N_i}$

把每个数组的 $H_i \in [0, \log_2 N_i]$ 映射到 $[0, 1]$：

- 比值 = 0 → 访问完全集中在一个槽位
- 比值 = 1 → 访问均匀分布，达到最大熵
- 比值 = 0.5 → 介于两者之间

**第二步——平均：** $\frac{1}{m} \sum_{i=1}^{m}$

对所有 $m$ 个数组取算术平均，得到一个 0~1 之间的全局数字，代表**整个程序当前数组访问的分布均匀程度**。

#### 与 SDS 的对比来理解

继续用回 4 槽位的例子（假设程序中只有一个数组）：

| 场景 | 访问分布 | unique_slots | SDS | $H_i$ | $E = H_i / 2$ |
|------|---------|-------------|-----|-------|---------------|
| A | 全部在槽位 0 | 1 | 1/4 = 0.25 | 0 | 0 / 2 = 0 |
| B | 各 25 次，均匀 | 4 | 4/4 = 1.0 | 2.0 | 2/2 = 1.0 |
| C | 70, 20, 5, 5 次，不均 | 4 | 4/4 = 1.0 | 1.26 | 1.26/2 = 0.63 |

注意 B 和 C 的 SDS 都是 1.0（4 个槽位全踩到了），但 $E$ 分别是 1.0 和 0.63——**SDS 饱和了，但 $E$ 仍然能区分差异**。这就是引入熵的价值。

#### 代码实现（array_state_runtime.c）

```c
float __afl_get_entropy_score(void) {
    if (array_tracker.num_arrays == 0) return 0.0f;
    float total = 0.0f;
    float max_entropy = log2f((float)MAX_INDEX_SLOTS);  // = 8.0

    for (int i = 0; i < array_tracker.num_arrays; i++) {
        array_state_t *arr = &array_tracker.arrays[i];
        if (arr->access_count == 0) continue;

        float ent = __afl_get_entropy(arr->array_id);
        total += ent / max_entropy;  // 归一化后累加
    }
    return total / (float)array_tracker.num_arrays;  // 取平均
}
```

### 4. SDS 与熵 $E$ 的对比

| 维度 | SDS（状态多样性得分） | $E$（归一化熵得分） |
|------|---------------------|-------------------|
| **度量内容** | 覆盖广度 | 分布均匀度 |
| **数据来源** | `visited_slots[256]` / `unique_slots` | `slot_access_count[256]` |
| **区分度** | 无法区分集中与均匀 | 能区分 |
| **取值范围** | $[0, 1]$ | $[0, 1]$ |
| **计算开销** | O(1)（直接读 unique_slots） | O(256)（需遍历所有槽位算分布） |
| **论文章节** | §3.3.2 | §3.4.2 |

### 5. 两者如何配合

```
SDS 大 + E 大 = 理想状态：覆盖广且分布均匀
SDS 大 + E 小 = 警告信号：虽然踩到的槽位多，但集中在少数区域反复访问
SDS 小 + E 大 = 初期正常：刚开始探索，少量槽位均匀分布
SDS 小 + E 小 = 探索不足：覆盖少且集中
```

在论文中，SDS 用于**引导变异策略**（§3.6 自适应调整），$E$ 用于**种子质量评估**（§3.5 融合评估 $Q = \alpha C_{cov} + (1-\alpha)E$）。

## 常见追问

### Q1：为什么不用更大的槽位数（比如 1024）？

256 是权衡选择。槽位数越多，粒度越细，但每个槽位需要 $-\log_2(1/256) = 3$ 次访问才能对熵值产生贡献（最小非零概率的检测阈值）。256 在实际测试中经验性地平衡了精度和收敛速度。

### Q2：$E$ 的计算要遍历 256 个槽位，性能开销大吗？

每次查询时确实要 O(256) 遍历，但 $E$ 只在**固定轮次间隔**（论文中每轮校准）才计算，不是每次数组访问都触发。相比 AFLGO 每秒数千到数万次执行的运行规模，这个开销可以忽略。

### Q3：为什么归一化用 $\log_2 256$ 而不是其他值？

因为 $\log_2 N_i$ 正好是 $H_i$ 的最大可能值——当 256 个槽位均匀分布时 $H_{max} = \log_2 256 = 8$。用它做分母保证 $E \in [0, 1]$，方便跨数组比较和后续融合加权。

归一化的本质不是"随便找个值除一下"，而是问"当前探索程度占最大可能探索程度的百分比"。只有用最大熵做分母，这个百分比才有意义。

### Q4：为什么用 $\log_2$ 而不是 $\ln$ 或 $\log_{10}$？

用 $\log_2$ 是因为这里处理的每个数组都有 256 = $2^8$ 个槽位，二进制对数正好对应"需要多少比特（多少次是非问题）来表达一个槽位"。这在信息论中是标准做法。

如果用 $\ln$（自然对数）或 $\log_{10}$ 也可以，绝对值不同，但除以各自最大熵归一化后，结果是一样的。论文统一用 $\log_2$ 是为了和"不确定性=需要问多少个是否问题"这个直觉保持一致。
