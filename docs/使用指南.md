## 二、构建系统

### 2.1 编译 LLVM Pass 插件

```bash
cd /workspace/code/passes/build
cmake .. -DLLVM_DIR=/usr/lib/llvm-11/cmake
make -j4
```

**产物：**
| 文件 | 说明 |
|------|------|
| `libarray_analysis_pass.so` | 静态分析 Pass（数组变量识别 + 影响力计算） |
| `libarray_instrument_pass.so` | 插桩 Pass（GEP 后插监控代码） |

### 2.2 编译运行时库

```bash
cd /workspace/code/runtime
clang-11 -c -O2 -fPIC array_state_runtime.c -o array_state_runtime.o
ar rcs libarray_state.a array_state_runtime.o
```

**产物：** `libarray_state.a` — 运行时状态采集静态库

### 2.3 编译修改版 AFLGO 模糊器

```bash
cd /opt/aflgo/afl-2.57b
cp /workspace/code/scripts/tmp-config.h config.h
cp /workspace/code/scripts/tmp-afl-fuzz.c afl-fuzz.c
AFL_NO_X86=1 make afl-fuzz
```

## 三、编译插桩版目标程序

### 3.1 单文件项目（以 mjs 为例）

```bash
cd /workspace/code/test_subjects/mjs

# Step 1: 编译所有源文件为 LLVM IR
for src in *.c; do
    aflgo-clang -O0 -g -S -emit-llvm -c "$src" -o "${src%.c}.ll"
done

# Step 2: 链接 IR 文件
llvm-link-11 *.ll -o mjs_all.ll

# Step 3: 数组插桩 Pass
opt-11 -load /workspace/code/passes/build/libarray_instrument_pass.so \
    -array-instrument mjs_all.ll -S -o mjs_instr.ll

# Step 4: 编译为可执行文件并链接运行时库
clang-11 mjs_instr.ll \
    /workspace/code/runtime/libarray_state.a \
    /opt/aflgo/instrument/aflgo-runtime.o \
    -o mjs_instr -lm
```

### 3.2 修改版 AFLGO 编译（cmake 项目示例）

对于使用 CMake 的项目（如 cjson、libpng），需要通过覆盖编译器方式使用 AFLGO：

```bash
cd /workspace/code/test_subjects/cjson
CC=/opt/aflgo/instrument/aflgo-clang \
CXX=/opt/aflgo/instrument/aflgo-clang++ \
    cmake .. -DCMAKE_BUILD_TYPE=Debug
make -j4
```

### 3.3 运行静态分析（单独查看数组信息）

```bash
opt-11 -load /workspace/code/passes/build/libarray_analysis_pass.so \
    -array-analysis mjs_all.ll -o /dev/null 2> analysis_report.log

# 查看分析结果
cat analysis_report.log
```

输出包含每个函数中的数组变量名称、类型、长度、作用域和影响力评分。

## 四、运行 AFLGO 模糊测试

### 4.1 准备种子和目标

```bash
# 创建种子目录
mkdir -p seeds
echo "0" > seeds/seed1

# 确定目标位置（文件:行号）
# 例如目标位置为 target.c:42，传递给 AFLGO
```

### 4.2 启动模糊测试（基线模式 — 仅 AFLGO）

```bash
AFL_NO_UI=1 AFL_SKIP_CPUFREQ=1 \
    /opt/aflgo/afl-2.57b/afl-fuzz \
    -i seeds -o output_baseline \
    -d -- ./target_baseline @@
```

### 4.3 启动模糊测试（引导模式 — AFLGO + 数组状态）

```bash
AFL_NO_UI=1 AFL_SKIP_CPUFREQ=1 \
AFL_ARRAY_DIVERSITY=1 \
    /opt/aflgo/afl-2.57b/afl-fuzz \
    -i seeds -o output_guided \
    -d -- ./target_guided @@
```

### 4.4 查看实验结果

```bash
# 统计信息
cat /workspace/code/test_subjects/mjs/experiment_output/default/fuzzer_stats

# 查看崩溃用例
ls -la /workspace/code/test_subjects/mjs/experiment_output/default/crashes/

# 查看数组状态反馈
cat /tmp/array_feedback.txt
```

## 五、环境变量参考

| 变量 | 说明 |
|------|------|
| `AFL_ARRAY_DIVERSITY=1` | 启用数组状态多样性评估 |
| `AFL_ARRAY_FEEDBACK_FILE=/path` | 指定反馈文件路径（默认 /tmp/array_feedback.txt） |
| `AFL_NO_UI=1` | 关闭 AFLGO 界面（Docker 中必须设置） |
| `AFL_SKIP_CPUFREQ=1` | 跳过 CPU 频率检查 |

融合权重通过修改 `config.h` 调整：

```c
#define FUSION_WEIGHT_ALPHA  0.5   // 路径距离权重
#define FUSION_WEIGHT_BETA   0.3   // SDS 多样性权重
#define FUSION_WEIGHT_GAMMA  0.2   // 香农熵权重
```

## 七、排错指南

### 7.1 cmake 找不到 LLVM

```bash
# 检查 LLVM 版本
llvm-config-11 --version
# 应输出 11.0.0
```

### 7.2 AFLGO 报 "No instrumentation detected"

目标二进制缺少 AFLGO 边覆盖率插桩。必须使用 `aflgo-clang` 或 `aflgo-clang++` 编译，不能用普通 `clang-11`。

### 7.3 AFLGO 报 "CPU frequency not supported"

```bash
export AFL_SKIP_CPUFREQ=1
```

### 7.4 反馈文件 /tmp/array_feedback.txt 不存在

运行时库在程序退出时写入该文件。可能原因：
1. 未设置 `AFL_ARRAY_DIVERSITY=1`
2. 程序崩溃后未执行到写入点
3. 程序无数组访问，反馈为空

### 7.5 Segmentation fault 运行错误

插桩版本在测试时可能触发数组越界导致崩溃，这是正常行为——说明正在测试的漏洞触发条件有效。
