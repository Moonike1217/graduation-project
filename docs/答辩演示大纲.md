# 答辩口头汇报要点

## 一、项目背景（1分钟）

- **问题**：传统 AFL/AFLGO 以代码覆盖率为导向，覆盖率到了不代表能触发数组越界。例如 `buffer[offset] = data` 被执行了，只有 `offset` 恰好超出边界才会崩
- **缺口**：现有模糊测试缺乏对**数组变量运行时状态**的精细化感知和针对性引导
- **我的工作**：在 AFLGO 定向引导的基础上，增加"数组状态维度"，追踪每个数组的索引访问模式，并用状态信息指导种子调度

## 三、工作原理

### 3.1 编译时：LLVM Pass 插桩

1. 静态分析 Pass 扫描 LLVM IR 中的 GEP 指令，识别数组变量并计算影响力分数
2. 插桩 Pass 在每个 GEP 后插入 `__afl_report_array_state(array_id, index, type, line)` 调用
3. 使用 **FNV-1a 哈希**（函数名 + 变量名）生成数组唯一 ID

### 3.2 运行时：状态采集与度量

- `__afl_report_array_state` 记录：数组 ID、索引值、读写类型、行号
- 统计每个数组的：访问次数、已访问槽位、访问频率分布
- 跑完后计算两个指标：
  - **SDS**（状态多样性得分）= 已覆盖槽位 / 总槽位，反映覆盖**广度**
  - **归一化香农熵 E** = 1/m Σ Hᵢ/log₂N，反映访问分布**均匀性**
- 写入 `/tmp/array_feedback.txt` 供调度器读取

### 3.3 调度时：双重引导融合

AFLGO 原有距离评分 + 数组状态多样性评分 → 综合得分 Q：
- Q = α·D' + β·S + γ·E
- α=0.5（距离权重），β=0.3（SDS权重），γ=0.2（熵权重）
- 高 Q 种子获得更多变异能量和更高的排队优先级

## 四、实验数据

在 4 个开源代码库上对比 AFLGO 基线 vs 本文工具，每组 1 小时：

| 指标 | mjs | cjson | lrzip | libpng |
|------|-----|-------|-------|--------|
| 路径增量 | +116 | +187 | +85 | +582 |
| 覆盖率增长 | +0.12% | +1.92% | +0.24% | +0.64% |
| 额外独特崩溃 | +3 | +6 | +2 | +6 |

### 结论

- 数组状态多样性引导在 4 个测试集上均有稳定提升
- cjson 和 libpng 提升最显著（数组操作密集）
- 三项指标（路径数、覆盖率、独特崩溃）均占优势

## 五、答辩可能被问到的点

1. **为什么用 FNV-1a 哈希？** 确定性 + 32 位 + 零依赖 + 三行代码 + IETF 标准
2. **多维数组怎么处理？** 嵌套 GEP 回溯，外层行访问（matrix）、内层元素访问（matrix#dim1）各自独立追踪
3. **指针变量会被误识别吗？** 不会，Pass 只处理数组类型变量，`const char *src` 这种不触发识别
4. **数组状态评分和 AFLGO 距离评分是什么关系？** 加权融合——综合得分 Q = α·D' + β·S + γ·E，距离评分保留最高权重（α=0.5）确保定向能力，状态多样性作为补充因子
5. **性能开销多大？** 每次数组访问增加一次函数调用，整体开销控制在 30% 以内
6. **多维数组怎么处理？** 嵌套 GEP 回溯，外层行访问、内层元素访问各自用独立 ID 追踪
