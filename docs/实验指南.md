## 一、环境准备

### 1.1 Docker 容器

```bash
# 构建容器
docker run -it --rm \
    -v "/Users/moonike/Desktop/graduation-project:/workspace" \
    -w /workspace ubuntu:18.04 bash
```

### 1.2 安装 LLVM 11 工具链

```bash
# 添加 LLVM 11 源
wget -O - https://apt.llvm.org/llvm-snapshot.gpg.key | apt-key add -
echo "deb http://apt.llvm.org/bionic/ llvm-toolchain-bionic-11 main" >> /etc/apt/sources.list
apt-get update
apt-get install -y clang-11 llvm-11-dev lld-11 llvm-11-tools libc++-dev
```

### 1.3 编译安装 AFLGO

```bash
git clone https://github.com/aflgo/aflgo.git /opt/aflgo
cd /opt/aflgo
make -C afl-2.57b
make -C instrument
make -C distance/distance_calculator
```

### 1.4 编译自定义 LLVM Pass 插件

```bash
cd /workspace/code/passes/build
cmake .. -DLLVM_DIR=/usr/lib/llvm-11/cmake
make -j4
```

预期产物：
- `libarray_analysis_pass.so` — 静态分析 Pass
- `libarray_instrument_pass.so` — 插桩 Pass

### 1.5 编译运行时库

```bash
cd /workspace/code/runtime
clang-11 -c -O2 -fPIC array_state_runtime.c -o array_state_runtime.o
ar rcs libarray_state.a array_state_runtime.o
```

### 1.6 编译修改版 AFLGO 模糊器

```bash
cd /opt/aflgo/afl-2.57b
cp /workspace/code/scripts/tmp-config.h config.h
cp /workspace/code/scripts/tmp-afl-fuzz.c afl-fuzz.c
AFL_NO_X86=1 make afl-fuzz
```

## 二、功能测试

论文表 5.2 ~ 表 5.5 对应四个功能模块的验证测试。

### 2.1 TC1：静态分析数组变量识别（表 5.2）

对目标程序编译 LLVM IR 并运行静态分析 Pass：

```bash
cd /workspace/code

# 以 mjs 为例
cd test_subjects/mjs
for src in *.c; do
    clang-11 -S -emit-llvm -g -O0 -c "$src" -o "${src%.c}.ll"
done
llvm-link-11 *.ll -o mjs_all.ll

# 运行静态分析 Pass
opt-11 -load /workspace/code/passes/build/libarray_analysis_pass.so \
    -array-analysis mjs_all.ll -o /dev/null 2> /tmp/analysis_mjs.log

cat /tmp/analysis_mjs.log
```

**预期输出**：每个函数中的数组变量名称、类型、长度、作用域和影响力评分。

对其他测试目标（cjson、lrzip、libpng）重复相同步骤。

### 2.2 TC2：数组状态监控插桩（表 5.3）

```bash
cd /workspace/code

# 插桩
opt-11 -load /workspace/code/passes/build/libarray_instrument_pass.so \
    -array-instrument test_subjects/mjs/mjs_all.ll -S -o /tmp/mjs_instr.ll 2>&1 | head -30

# 编译可执行文件
clang-11 /tmp/mjs_instr.ll \
    /workspace/code/runtime/libarray_state.a \
    /opt/aflgo/instrument/aflgo-runtime.o \
    -o /tmp/mjs_instr -lm

# 运行
echo '{"key":"value"}' > /tmp/input.json
/tmp/mjs_instr input.txt 2>&1 || true

# 查看反馈文件
cat /tmp/array_feedback.txt
```

验证插桩后程序可正常编译运行，且运行时正确记录数组访问信息。

### 2.3 TC3：数组状态多样性评估（表 5.4）

在不同输入下运行插桩版本，观察 SDS 和熵值的变化。

```bash
# 用不同索引值的输入测试，观察 SDS 和熵值增长
for input in "0" "5" "10" "50" "100" "255"; do
    echo "$input" > /tmp/input.txt
    echo "=== 输入: $input ==="
    /tmp/mjs_instr /tmp/input.txt 2>&1 || true
    echo "--- SDS/Entropy ---"
    cat /tmp/array_feedback.txt
    echo ""
done
```

**预期**：多样性指标随输入多样性增加而增长。

### 2.4 TC4：测试用例选择引导（表 5.5）

在启用 `AFL_ARRAY_DIVERSITY=1` 和不启用两种模式下运行 AFLGO 对比：

```bash
# 基线模式（无数组状态引导）
AFL_NO_UI=1 AFL_SKIP_CPUFREQ=1 \
    /opt/aflgo/afl-2.57b/afl-fuzz \
    -i seeds -o /tmp/output_baseline \
    -V 60 -d -- /tmp/mjs_instr @@

# 引导模式（启用数组状态多样性）
AFL_NO_UI=1 AFL_SKIP_CPUFREQ=1 \
AFL_ARRAY_DIVERSITY=1 \
    /opt/aflgo/afl-2.57b/afl-fuzz \
    -i seeds -o /tmp/output_guided \
    -V 60 -d -- /tmp/mjs_instr @@
```

对比两种模式的崩溃发现数量。

## 三、效果测试

### 3.1 准备工作：编译四个测试目标的插桩版本

每个测试目标需要编译两个版本：
- **基线版本**：仅 AFLGO 插桩（使用 `aflgo-clang`）
- **引导版本**：AFLGO 插桩 + 数组状态插桩

#### mjs（轻量级 JavaScript 引擎）

```bash
cd /workspace/code/test_subjects/mjs

# 基线版本
aflgo-clang -O0 -g *.c -o /tmp/mjs_baseline -lm

# 引导版本
for src in *.c; do
    aflgo-clang -O0 -g -S -emit-llvm -c "$src" -o "${src%.c}.ll"
done
llvm-link-11 *.ll -o mjs_all.ll
opt-11 -load /workspace/code/passes/build/libarray_instrument_pass.so \
    -array-instrument mjs_all.ll -S -o mjs_instr.ll
clang-11 mjs_instr.ll \
    /workspace/code/runtime/libarray_state.a \
    /opt/aflgo/instrument/aflgo-runtime.o \
    -o /tmp/mjs_guided -lm
```

#### cjson（JSON 解析器）

```bash
cd /workspace/code/test_subjects/cjson

```

### 3.2 运行对比实验

对每个测试目标，分别用基线版本和引导版本运行 AFLGO：

```bash
# ===== 以 mjs 为例 =====
mkdir -p /tmp/seeds /tmp/output_baseline /tmp/output_guided
echo "" > /tmp/seeds/seed1   # mjs 接受空输入

# 基线版本（1 小时）
AFL_NO_UI=1 AFL_SKIP_CPUFREQ=1 \
    /opt/aflgo/afl-2.57b/afl-fuzz \
    -i /tmp/seeds -o /tmp/output_baseline \
    -V 3600 -d -- /tmp/mjs_baseline -f @@

# 引导版本（1 小时）
AFL_NO_UI=1 AFL_SKIP_CPUFREQ=1 \
AFL_ARRAY_DIVERSITY=1 \
    /opt/aflgo/afl-2.57b/afl-fuzz \
    -i /tmp/seeds -o /tmp/output_guided \
    -V 3600 -d -- /tmp/mjs_guided -f @@
```

对其他三个测试目标重复上述流程。
