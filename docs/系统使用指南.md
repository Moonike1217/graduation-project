
## 二、构建系统

### 2.1 从零构建（首次使用）

```bash
cd /src/my_pass/build
rm -rf *                            # 清空之前的构建缓存
cmake ..                            # 配置 CMake
make -j4                            # 编译全部 (MyArrayPass.so + libafl_array_state.a)
```

**产物列表：**

| 文件 | 说明 |
|------|------|
| `MyArrayPass.so` | LLVM Pass 插件 |
| `libafl_array_state.a` | 运行时状态采集静态库 |
| `custom_mutator.so` | AFL++ 自定义变异器 |

### 2.2 快速构建（已有缓存）

```bash
cd /src/my_pass/build
make -j4
```

## 三、运行测试流水线

### 3.1 一键测试：编译 → 插桩 → 链接 → 运行

```bash
cd /src/my_pass/build
make run_tests
```

该命令执行以下步骤：
1. `clang-19` 将 `test/test.c` 编译为 LLVM IR (`test.ll`)
2. `opt-19` 加载 `MyArrayPass.so` 对 LLVM IR 进行插桩 (`test_instrumented.ll`)
3. `clang-19` 链接运行时库，生成可执行文件 (`test_app`)
4. 分别用索引值 1, 9, 11, -1, 33, 9999 运行 `test_app`

**预期输出：**
- 静态分析报告：每个函数中的数组信息
- `[Instrumented]` 标记：显示被插桩的数组访问
- `[ArrayAccess]` 记录：每次数组访问的 ID、索引、类型
- `Segmentation fault`：越界索引触发崩溃（**这是正常的，说明漏洞检测生效**）

### 3.2 仅编译插桩版本（不运行）

```bash
cd /src/my_pass/build
make compile_afl_test              # 编译 AFL++ 插桩版本 test_afl_instr
make build_mutator                 # 编译自定义变异器 custom_mutator.so
```

## 四、运行 AFL++ 模糊测试

### 4.1 快速实验（60 秒）

```bash
cd /src/my_pass/build
mkdir -p experiment_seeds
echo "0" > experiment_seeds/seed1
echo "5" > experiment_seeds/seed2

AFL_NO_UI=1 AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1 \
    afl-fuzz -i experiment_seeds -o experiment_output \
    -V 60 -d -- ./test_afl_instr @@
```

**参数说明：**

| 参数 | 含义 |
|------|------|
| `AFL_NO_UI=1` | 关闭 UI（在 Docker 中必须设置） |
| `AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1` | 不因测试程序无崩溃而报错 |
| `-i experiment_seeds` | 种子输入目录 |
| `-o experiment_output` | 输出目录 |
| `-V 60` | 运行时长（秒） |
| `-d` | 跳过确定性阶段（加快速度） |
| `-- ./test_afl_instr @@` | 目标程序，`@@` 被替换为输入文件路径 |

### 4.2 运行更长时间（生产模式）

```bash
cd /src/my_pass/build
AFL_NO_UI=1 \
    afl-fuzz -i experiment_seeds -o experiment_output \
    -V 3600 -d -- ./test_afl_instr @@
```
（`-V 3600` = 1 小时）

### 4.3 使用自定义变异器

```bash
cd /src/my_pass/build
AFL_CUSTOM_MUTATOR_LIBRARY=/src/my_pass/build/custom_mutator.so \
    AFL_NO_UI=1 \
    afl-fuzz -i experiment_seeds -o experiment_output \
    -V 60 -d -- ./test_afl_instr @@
```

### 4.4 查看实验结果

```bash
# 查看统计信息
cat /src/my_pass/build/experiment_output/default/fuzzer_stats

# 查看崩溃用例
ls -la /src/my_pass/build/experiment_output/default/crashes/

# 查看崩溃内容
cat /src/my_pass/build/experiment_output/default/crashes/id:*

# 查看种子队列
ls /src/my_pass/build/experiment_output/default/queue/
```

## 五、分步执行（手动模式）

如果想理解每个步骤，可以手动执行：

### 5.1 Step 1：生成 LLVM IR

```bash
cd /src/my_pass/build
clang-19 -S -emit-llvm -fno-discard-value-names -g -O0 \
    -Xclang -disable-O0-optnone \
    /src/my_pass/test/test.c \
    -o test.ll
```

产物：`test.ll`（文本格式的 LLVM IR）

### 5.2 Step 2：LLVM Pass 插桩

```bash
opt-19 -load-pass-plugin=./MyArrayPass.so \
    -passes="my-array-pass" \
    test.ll -S -o test_instrumented.ll
```

产物：`test_instrumented.ll`（插桩后的 LLVM IR）

查看插桩效果：
```bash
grep "__afl_report_array" test_instrumented.ll
```

### 5.3 Step 3：编译链接可执行文件

```bash
clang-19 test_instrumented.ll -L. -lafl_array_state -o test_app
```

产物：`test_app`（插桩后的可执行文件）

### 5.4 Step 4：运行测试

```bash
echo "5" > input.txt
./test_app input.txt
```

## 六、用自己的程序测试

如果你想用 `MyArrayPass` 插桩自己的 C 程序：

```bash
# 1. 编译自己的程序为 LLVM IR
clang-19 -S -emit-llvm -g -O0 -Xclang -disable-O0-optnone \
    /path/to/your_program.c \
    -o your_program.ll

# 2. 用 MyArrayPass 插桩
opt-19 -load-pass-plugin=/src/my_pass/build/MyArrayPass.so \
    -passes="my-array-pass" \
    your_program.ll -S -o your_program_instr.ll

# 3. 链接运行时库，生成可执行文件
clang-19 your_program_instr.ll \
    -L/src/my_pass/build -lafl_array_state \
    -o your_program_instr

# 4. 用 AFL++ 模糊测试
AFL_NO_UI=1 afl-fuzz -i seeds -o out \
    -V 60 -- ./your_program_instr @@
```

## 八、排错指南

### 8.1 cmake 找不到 LLVM

```bash
# 检查 LLVM 版本
llvm-config --version
# 应该输出 19.1.1
```

### 8.2 链接时报 __afl_area_ptr 未定义

这是因为编译时未使用 AFL++ 编译器。解决方案：
- 独立测试模式：已通过 `AFL_RUNTIME=0` 解决
- AFL++ 模式：必须用 `afl-clang-fast` 编译

### 8.3 AFL++ 报 "input directory does not seem to be valid"

种子目录为空或种子文件不符合要求：
```bash
mkdir -p seeds
echo "0" > seeds/seed1  # 种子文件必须有内容
```

### 8.4 容器不存在

```bash
# 重新创建
docker run -d -it --name aflplusplus_env \
    -v "/Users/moonike/Desktop/graduation-project:/src" \
    aflplusplus/aflplusplus bash
```
